# A股集合竞价数据采集器

- 当前版本：0.1.0
- 当前状态：本地核心完成；生产部署与批量快照实盘门槛阻塞
- 更新时间：2026-08-24
- 检索别名：集合竞价采集器、A股竞价快报、09:25竞价额、auction collector

## 一句话定位

每个 A 股交易日自动采集 9:25 最终开盘集合竞价，保存个股历史并生成四板、全 A、Top20、行业与数据质量报告。

## 解决的问题

提供可复核、可留存、可幂等重跑的集合竞价数据真源，避免把 9:15–9:24 虚拟撮合或 9:30 连续竞价误算为最终竞价额，并为 9:35 前的竞价快报提供统一 JSON。

## 目标用户和主要使用场景

- Kevin 每日查看 A 股集合竞价总量、板块差异、Top20 与行业集中度。
- “资金显微镜”或其他程序读取 `report.json` 生成竞价快报。
- 数据异常时读取原始 JSON、SQLite 和日志复盘。

## 当前页面、界面和模块地图

本项目没有 Web 页面或 Dashboard。模块为：`eastmoney.py` 负责数据源；`core.py` 负责任务编排和门槛；`storage.py` 负责 SQLite、汇总与导出；`cli.py` 是命令行入口；`deploy/systemd/` 是 Linux 定时模板。

## 所有当前有效功能

- 获取上海主板、深圳主板、创业板、科创板股票池并排除其他证券类型。
- 按 `trends2` 09:26 行提取逻辑 09:25 的最终竞价价、量、额。
- 09:26 批量快照必须通过固定 20 只逐股真源 20/20 同时点校验才可使用。
- 批量校验失败时拒绝信任快照并降级逐股采集；不完整结果标记 poor。
- 保存原始响应、个股明细、四板和全 A 汇总、Top20、行业汇总、质量报告与日志。
- SQLite 主键幂等重跑，复用同日已成功个股。
- 缺失率、历史异常、负数、重复代码、板块/全 A 对账守卫。

## 当前业务内容、数据和字段

个股主字段：日期、代码、名称、交易所、板块、逻辑竞价时间、源时间、竞价手数、竞价额、竞价价、前收、涨跌幅、行业、新股标记、有效性、状态、来源、抓取时间、原始路径、错误。

板块字段：date、board、auction_amount、previous_auction_amount、change_amount、change_pct、stock_count、valid_stock_count、missing_stock_count、data_quality。统一报告含 market_total、boards、top20、industries、quality、generated_at。

## 完整操作流程

1. systemd 在工作日 09:26:00 启动并等待至 09:26:05。
2. 获取四板股票池与分页批量快照并保存原始 JSON。
3. 对四板各 5 只固定样本读取 `trends2` 09:26/f57。
4. 批量 f6 与逐股 f57 20/20 一致才接受全市场快照，否则降级。
5. 个股数据幂等写入 SQLite。
6. 读取上一交易日和最近历史，生成四板/全 A 环比、Top20、行业汇总和质量守卫。
7. 导出 CSV/JSON 并写日志；poor 报告明确禁止确定性交易判断。

## 数据来源和更新方式

- 主参考真源：东方财富 `push2.eastmoney.com/api/qt/stock/trends2/get`，源行 09:26，金额 f57。
- 批量候选源：东方财富 `clist/get` 09:26 分页快照，金额 f6；未通过下一交易日同时点门槛前不视为生产真源。
- 行业和股票池：东方财富市场/证券类型过滤器与 f100 行业字段。
- 20 只字段语义已于 2026-08-24 与独立结构化逐笔 09:25 成交交叉验证通过。

## 保存、导入、导出和备份格式

- 原始数据：`raw/YYYY-MM-DD/*.json`。
- 历史数据库：`database/auction_data.db`。
- 每日导出：`data/YYYY-MM-DD/stock_auction.csv`、`board_summary.csv`、`top20.csv`、`industry_summary.csv`、`report.json`、`quality.json`。
- 备份至少保留 database、data 与 raw；不依赖第二天回溯上游。

## 配置项和默认值

- 时区 Asia/Shanghai；启动 09:26:00；批量有效窗口 09:26:05–09:28:59；实时截止 09:29:30。
- 并发 6，允许 1–12；单请求超时 15 秒；最多重试 2 次并指数退避。
- 新股 30 天内；缺失率 `<1%` good、`1%–3%` warning、`>3%` poor。
- 至少 5 日历史后，全 A 低于中位数 0.2 倍或高于 5 倍为 poor。

## 技术栈、运行原理和关键架构

Python 3.11+、requests、标准库 concurrent.futures/sqlite3/csv/json、systemd timer。正确性采用“逐股真源 + 批量候选源 + 同时点样本门禁”；持久化采用 SQLite WAL 和复合主键幂等更新。

## 依赖和运行环境

Python 3.11+、requests 2.32–2.x。Linux 服务器推荐 systemd，Windows 本地可测试。服务器需要能访问东方财富结构化接口且系统时间同步正常。

## 权限与安全边界

- 不抓网页 HTML，不破解账号，不保存密码、Token、Cookie、验证码或券商凭证。
- systemd 使用普通用户、严格文件系统保护，只写项目 data/database/logs/raw/state。
- 原始行情再分发需遵守数据源条款。
- 盘后批量 f6 是全天累计额，程序禁止在有效窗口外将其当集合竞价额。
